# devops/ audit — findings & plan of action

> **STATUS: all four phases executed 2026-07-25.** Version sweep, consistency/scope-fence pass, the `devops-engineer` agent + slash command, and the standalone `devops` marketplace plugin (with the CLAUDE.md DevOps catalog + README rows) are all done. Findings F1–F9 are closed; F10 remains a recorded decision (three CI skills stay separate).

**Date:** 2026-07-12
**Scope audited:** all 9 skills in `devops/` (`docker`, `kubernetes`, `iac-bicep-terraform`, `aws-deployment`, `azure-deployment`, `github-actions`, `gitlab-ci`, `azure-pipelines`, `environment-config`) — ~3,000 lines, full read — plus every inbound reference from the shipped domains (`observability/*`, `qa/cicd/ci-conventions`, `fe-blazor`, `auth/_shared/auth0-concepts`, `backend/*`) and the marketplace wiring.
**Method:** full read of every SKILL.md against the library's conventions (CLAUDE.md Stack defaults + version policies, `.skill-template/agent.md`, the domain-catalog pattern every shipped domain follows), cross-reference resolution in both directions, and technical spot-checks of the recipes.

---

## Overall assessment

The content quality is high: all nine skills follow the house SKILL.md shape (frontmatter with Triggers + Do-NOT routing, When to use / When NOT / Inputs / recipes / Rules / What NOT to do / Generation steps / Handoffs), the security posture is uniformly correct and current (OIDC/WIF everywhere, no static credentials, Managed Identity/IRSA, OAC-only S3, non-root containers, plan-before-apply), and the intra-domain scope fences (docker ↔ kubernetes ↔ deployment ↔ pipelines ↔ IaC ↔ config) are cleanly drawn and mutually consistent. Nothing here is wrong enough to be dangerous.

The problems are of two kinds. **Ship-readiness:** the domain is missing everything that makes a folder a *domain* in this library — no orchestrator agent (fe-blazor.md:97 explicitly points the human at raw skills because "No agent yet"), no marketplace plugin, no CLAUDE.md catalog section, and CLAUDE.md fences the folder as under-construction while five shipped domains already hand off to it (observability names `devops/kubernetes` + `devops/iac-bicep-terraform` in every agent; `qa/cicd/ci-conventions` routes deploy pipelines here). **Internal drift:** two skills (`docker`, `github-actions`) were updated to the current stack defaults (.NET 10 primary, Node 24 LTS, with a Version-policy section) while the other five that mention stack versions still teach **Node 20 (EOL Apr 2026) and .NET 8 as primary** — the exact "never up-level/down-level" invariant the library enforces everywhere else is simply absent from them. Plus a handful of consistency defects: the gitlab-ci skill ships an Allure report-generation job that the github-actions skill (correctly) fences off to the QA domain, two skills hedge `devops/environment-config` as "(when authored)" although it sits authored in the same folder, and one recipe recommends Promtail, which the observability domain has standardized away from (Alloy; Promtail deprecated/EOL 2026).
