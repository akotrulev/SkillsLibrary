# Release and signing — audit fragment (section T)

Rows `T1…` are permanent. A stack's conformance checklist section **T — Release & signing** holds no rows of its own: it takes the rows below whose `Stacks` column names its stack (`rn`, `ios`, `android`), and a finding `T4` is row T4 here. Append new rows at the end with the next number; never renumber.

**How to read a row.** *Check* = the invariant. *Violation looks like* = what disqualifies it. *Find it with* = a mechanical lead — a hit is never a finding until the code is read. *Sev* = default severity. A row marked **requires dynamic test → `qa-security`** cannot be proven from source and is reported unverified, never as passed. A row whose evidence lives only in a console (Play Console, App Store Connect, EAS dashboard) is reported as `likely mismatch — verify in the console`.

Recipes use `rg`. Globs: `rn` → `app.json`, `app.config.*`, `eas.json`, `package.json`, `*.ts,*.tsx`, `.eas/workflows/*.yml`; `ios` → `*.pbxproj`, `Info.plist`, `Fastfile`, `Matchfile`, `ci_scripts/*`; `android` → `*.gradle*`, `*.kts`, `*.properties`, `*.xml`.
