# k6 load-test standards

Severity tags as in the core rules. The codebase wins where it consistently does otherwise. k6 scripts run in the k6 runtime, not Node: Node-side tooling around them follows the core rules.

- Every scenario states its workload model and gates before it runs, as `thresholds` (p95/p99 latency, error rate), never prose. *major*
- Open-loop `arrival-rate` executors by default; closed-loop `vus` only for a fixed concurrency cap. Do not mix the two in one `scenarios` block without meaning it. *major*
- Every `http.*` call carries `tags: { name: '…' }` and thresholds are keyed per route; never one aggregate `http_req_duration`. *major*
- A `check()` feeds a Rate or Counter that a threshold gates; a failed check alone gates nothing. *major*
- `BASE_URL`, tokens and tunables come from `__ENV`; nothing hardcoded. *blocker*
- `preAllocatedVUs` sized from target RPS × p95 seconds + 20%; no unbounded `maxVUs` or open-ended run. *minor*
- Fixtures are seeded in `setup()` and removed in `teardown()`, ids namespaced by `__VU` + `Date.now()`. *major*
- No `console.log` in the steady state, no `JSON.parse(JSON.stringify(…))` clones, no `sleep(0)` in an arrival-rate loop. *minor*
- Imports are `k6` / `k6/*` only, or a bundle; no Node APIs or npm runtime imports in a script run directly. *major*
- The k6 image is pinned, never `latest`. *minor*
- Load only an environment you are authorized to load and that is sized for it; smoke profile first. *blocker*
