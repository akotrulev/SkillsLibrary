# Security — audit fragment (section K)

Rows `K1…` are permanent. A stack's conformance checklist section **K — Security** holds no rows of its own: it takes the rows below whose `Stacks` column names its stack (`rn`, `ios`, `android`), and a finding `K3` is row K3 here. Append new rows at the end with the next number; never renumber.

**How to read a row.** *Check* = the invariant. *Violation looks like* = what disqualifies it. *Find it with* = a mechanical lead — a hit is never a finding until the code is read. *Sev* = default severity (blocker — a hard security rule break). *MASWE* = the weakness id; the MASVS control and MASTG tests are in `SKILL.md`. A row marked **requires dynamic test → `qa-security`** cannot be proven from source: report it **unverified**, never passed, and hand the question to `mobile-runtime-testing`. Every K report ends with the carve-out line from `SKILL.md`.

Recipes use `rg`. Globs: `rn` → `*.ts,*.tsx,*.js`, `app.json`, `app.config.*`; `ios` → `*.swift`, `Info.plist`, `*.entitlements`; `android` → `*.kt,*.kts,*.xml`, `AndroidManifest.xml`.
