# Feature document standards

A feature is documented as three files from one trace: `<NNN>-<slug>.md` (Level 1, the client guide), `<NNN>-<slug>.behind-the-scenes.md` (Level 2, plain-language connections) and `<NNN>-<slug>.technical.md` (Level 3, developers and AI). It is evidence-based reverse documentation. Apply these when you write one, or edit one because the code changed. Severity: **blocker** states what nobody can check or confirmed, **major** weakens the evidence or the reader's grasp, **minor** is form. Where the project consistently does otherwise, follow it.

**All levels**

- All three files exist and each links the other two in its header; the levels never contradict each other. A fact is explained at the level its reader needs and cited at the others. *major*
- Every file carries `**Audience:**` (`shareable` on Level 1, `internal` on Levels 2 and 3; only a person promotes Level 2 to `shareable`) and its stamp line (`**Derived from:**` on KB areas, `**Generated by**` on feature documents). On Levels 1 and 2 the metadata closes the file in `## About this document` (Level 2 keeps `**Audience:** internal` on top, beside `**Levels:**`, which stays on top everywhere); Level 3 keeps the whole block on top. *major*
- Every file carries its own stamp line with the commit (`**Derived from:** … @ <sha>` on KB areas, `**Generated by** … @ <commit>` on feature documents); the three files of a set carry the same commit after a run. When any one level is stale against `HEAD`, all three are reconciled and re-stamped with `Last updated`. *major*
- `doc-lint.py --dir <folder>` (shipped in `doc-business-model`'s `scripts/`) exits 0 before handing off; every WARN is fixed or explained. A `#confirmed` row in Level 3 is a WARN a human may have caused: it is never removed to silence the lint. *major*
- Every parameter, formula, threshold, step, branch, connection, timing and failure behaviour stated in Levels 1 or 2 has a row in Level 3's evidence index: `#observed` cites `file:line` read in this session, `#inferred` names its open question, a negative claim names its search. *blocker*
- Never write `#confirmed`; promotion is a human act. A row a human confirmed is not yours to change: escalate the contradiction. *blocker*
- Never invent a purpose. An inferred intent reads as uncertainty in Levels 1 and 2 ("appears to exist so that…") and is a row in Open questions. *blocker*
- Optional sections are dropped, never padded; the negative search that proved the absence is a row in Level 3. *minor*
- Code that is wired to a trigger outside the repository (a message nothing in the repo publishes, a handler whose caller is another service) is documented as a capability, with a Level 3 finding and an open question "who triggers this?". Code with no trigger anywhere is unreachable. *major*
- Nothing unreachable is written up as a capability. Defects go to Level 3's Findings, routed to their owner with the boundary condition that makes them bite, never into Levels 1 or 2 as intended behaviour. *major*
- When the code moves, update all three levels in place: re-read every citation at the current commit, re-stamp the headers, re-run the example. A drifted `file:line` is worse than none. A set in the old shape (`## How it works`, no `## Who uses it`) is updated into the new one section by section, never deleted and regenerated; `doc-lint.py --kept-from <rev>` must show no `fact-kept` line left unexplained. *major*
- `<NNN>` is never renumbered or reused. Nothing is written into `docs/business-model/`; cite a KB id rather than restating it. *minor*

**Level 1 — the guide**

- Opens with `## Who uses it`, then `## How it fits together` (key ideas and one Mermaid diagram), then one `## For <person>` section per person, in the order they meet the area, with a `### <task>` per thing they do in lifecycle order. A task has a `**Where:**` path, steps that are the person's own actions, and `**What happens next**` holding only what they then see, receive or are charged. Optional: `## What happens automatically`, `## Rules and limits`, `## A <period> in numbers`, `## Good to know`, `## Related areas`; then `## Open questions` and `## About this document`. *major*
- Bold is only a screen label that appears in Level 3's vocabulary; a task whose screen the trace did not find carries no `**Where:**` and no label. Callouts are `[!NOTE]`, `[!TIP]`, `[!IMPORTANT]` and `[!WARNING]` (only for what cannot be undone or charges money), at most one per task. *major*
- Internal ids (`AREA-`, `FLOW-`, `ENT-`…) appear only in `## About this document`; an inferred purpose appears only in Open questions. Length: guide 2,500 words, Level 2 3,000; detail over the cap moves down a level, never dropped. *major*

- Uses the client's own terms from the trace's `Client vocabulary` table, and a *What stops it* row quotes the exact user-facing message; each term is mapped to its code name — in `glossary.md` for KB areas, in Level 3's *Business ↔ code vocabulary* for a feature set. A client's own technical-sounding word stays in Levels 1–2 only when it is listed in the first column of that Level 3 table. *major*
- Client language only: no class, method, table or column names, file names, status codes, exception types, framework nouns, jargon (endpoint, payload, handler, idempotent…), tier tags or `file:line`, and no evidence table. A word that needs defining is replaced. *major*
- The worked example is mandatory, numeric whenever there is a calculation, threshold, layered setting or time-based process. Every number used as a rule is the code's exact value, the arithmetic is recomputed after any change, one cast runs throughout, and it never extends past what the code says. *major*
- A formula is plain-text math on its own line with `Where:`, rounding and conventions stated; never code. *major*
- A timing or delivery guarantee ("exactly once", "at most one/once", "immediately", "instantly", "as soon as", "in real time", "right away") is written in Levels 1–2 only where the code shows it and an evidence-index row backs it; the lint warns on each, and each is fixed or explained. *major*

**Level 2 — behind the scenes**

- Follows the guide's `## For <person>` sections and `### <task>` headings, same names, same order, and adds none; it may leave a task out. *major*

- Plain language with only the everyday technical words the skill allows (database, background job, retry, queue, outside service, switch…), each explained in passing; the same banned list as Level 1 for code nouns. Third-party services are named by product. *major*
- States behaviour neutrally. The words bug, defect, flaw, broken, wrong, mistake, vulnerability and "should have" are lint warnings in Levels 1 and 2, each fixed or explained; quoted product text is exempt. A statement that is also a Level 3 finding has an evidence-index row citing it (`see **F1**`). *major*
- A lane with nothing in it is dropped; "What the person notices if a later step fails" appears only when there is a later step. In a KB run, a branching path links its `FLOW-nnn` and is not redrawn. *minor*
- The parts are named once, in plain role names, used identically in every flow, diagram and table and mapped to code names in Level 3. *major*
- Every flow shows, in numbered steps, the lanes it uses: "Straight away (while the person waits)", "Afterwards (in the background)", "On a schedule". A guarantee the code does not show (ordering, exactly-once, retry) is stated as unknown, never assumed. *major*

**Level 3 — the technical reference**

- Every heading in the shape is present; a section with nothing to report states the search that found nothing. Rows of the Entry points, Rules, Data, Events, Integrations, Configuration, Errors and Findings tables carry local ids (technical open questions carry `T` ids); other tables carry none. Every row holds one fact with its evidence on the same row. *major*
- Evidence-index Section cells cite the flow heading and step (`Booking a seat · step 3`, or `steps 1–5`) or the section name; every flow of Levels 1 and 2 has a row, and every `see **X**` resolves to a row id in Level 3. *major*
- State machines and multi-participant flows are Mermaid diagrams; every refused transition is listed. *minor*
- Configuration records key names and defaults, never a secret's value. *blocker*
- Findings carry a boundary condition and a route. *minor*
- Level 3 runs to about 4,000 words, not counting the evidence index; past that it splits into `<name>.technical.<topic>.md` files, which the lint reads together with the main file. *minor*
