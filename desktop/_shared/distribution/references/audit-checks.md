# Distribution, signing and updates — audit fragment (section L)

Rows `L1…` are permanent. A platform's conformance checklist section **L — Distribution & signing** holds no rows of its own: it takes the rows below whose `Platforms` column names its platform (`macos`, `windows`), and a finding `L4` is row L4 here. Append new rows at the end with the next number; never renumber.

**How to read a row.** *Check* = the invariant. *Violation looks like* = what disqualifies it. *Find it with* = a mechanical lead; a hit is never a finding until the code is read. *Sev* = default severity (`blocker` / `major` / `minor` / `nit`, plan §8.3). A row marked **requires dynamic test → `qa-security`** cannot be proven from source and is reported unverified, never as passed. A row whose evidence lives only in a console (App Store Connect, Partner Center, the Azure portal) says **console only** and is reported unverified.

Recipes use `rg`. Globs: `macos` → `*.swift,*.plist,*.entitlements,*.xcconfig,*.pbxproj,Package.swift,Fastfile,ExportOptions.plist,.github/**`; `windows` → `*.cs,*.csproj,*.appxmanifest,*.appinstaller,*.props,global.json,*.vcxproj,.github/**,azure-pipelines*.yml`.
