# Observability — audit fragment (section U)

Rows `U1…` are permanent. A stack's conformance checklist section **U — Observability & logging** holds no rows of its own: it takes the rows below whose `Stacks` column names its stack (`rn`, `ios`, `android`), and a finding `U3` is row U3 here. Append new rows at the end with the next number; never renumber.

**How to read a row.** *Check* = the invariant. *Violation looks like* = what disqualifies it. *Find it with* = a mechanical lead — a hit is never a finding until the code is read. *Sev* = default severity. A row marked **requires dynamic test → `qa-security`** cannot be proven from source and is reported unverified, never as passed. The gateway and Collector side is outside this repo's evidence — report it as `likely mismatch — verify with observability-engineer-<stack>`.

Recipes use `rg`. Globs: `rn` → `*.ts,*.tsx`, `app.json`, `app.config.*`, `package.json`; `ios` → `*.swift`, `Info.plist`, `*.xcprivacy`; `android` → `*.kt,*.kts`, `*.gradle*`, `*.xml`.
