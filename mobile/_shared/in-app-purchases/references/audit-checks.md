# In-app purchases — audit fragment (section X)

Rows `X1…` are permanent. A stack's conformance checklist section **X — In-app purchases** holds no rows of its own: it takes the rows below whose `Stacks` column names its stack (`rn`, `ios`, `android`), and a finding `X3` is row X3 here. Append new rows at the end with the next number; never renumber.

**How to read a row.** *Check* = the invariant. *Violation looks like* = what disqualifies it. *Find it with* = a mechanical lead — a hit is never a finding until the code is read. *Sev* = default severity (blocker — an unenforced entitlement or a store rejection). A row marked **console only** is reported as `likely mismatch — verify in App Store Connect / Play Console`, **never as passed**. A row marked **requires dynamic test** cannot be proven from source and is reported unverified (`qa-security` / the `qa-mobile-*` peer).

Recipes use `rg`. Globs: `rn` → `*.ts,*.tsx,*.js`, `app.json`, `app.config.*`, `package.json`; `ios` → `*.swift`, `*.storekit`, `*.entitlements`; `android` → `*.kt,*.kts,*.xml`, `build.gradle*`, `libs.versions.toml`.
