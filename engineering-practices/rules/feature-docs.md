# Feature document standards

A feature is documented as one guide from one trace: `<NNN>-<slug>.md`, written for the people who use the product — every role, administrators included — and for the business analysts and the product owner who read along, with a few screenshots in `screenshots/<NNN>-<slug>/`. It is evidence-based reverse documentation. Apply these when you write one, or edit one because the code changed. Severity: **blocker** states what nobody can check or confirmed, **major** weakens the evidence or the reader's grasp, **minor** is form. Where the project consistently does otherwise, follow it. When the feature is documented as the closing task of a delivery plan (`DOC1`), the run also writes a delivery note to `docs/deliveries/<NNN>-<plan-slug>.md`; it is outside this file's scope and `doc-business-model`'s delivery-note reference owns its shape.

**The file**

- One guide per feature; no `.behind-the-scenes.md` or `.technical.md` beside it — those levels are retired, and a leftover one is read as a lead and deleted when the guide is next updated. *major*
- `## About this document` closes the file: `**Created:**`, `**Last updated:**` once updated, `**Describes:**` the date the product was read, and `**Screenshots:**` — `captured from <environment name> on <date>`, `pending — <why>`, `waived — <the person's reason>`, or absent when the guide has no screen. Never an environment address or a login. *major*
- The last line of the file is one stamp comment: `<!-- guide · source: be-feature-documenter @ <commit> · stories: <ids, when used> · audience: shareable -->`. Internal ids and story ids appear only there. The visible block carries no `**Id:**`, `**Owned by:**`, `**Derived from:**`, `**Generated by**`, `**Models:**` or `**Audience:**` line. *major*
- `doc-lint.py --dir <folder>` (shipped in `doc-business-model`'s `scripts/`) exits 0 before handing off; every WARN is fixed or explained. *major*
- When the code moves, update the guide in place: fold answered questions first, re-check what changed against the code, re-stamp, re-run the example, re-capture the screenshots of the tasks whose screen or steps changed. A guide in an earlier shape is brought into this one in the same file, with the same `**Created:**` and every fact kept — never deleted and regenerated; `doc-lint.py --kept-from <rev>` must show no `fact-kept` line left unexplained. *major*
- `<NNN>` is never renumbered or reused. Nothing is written into `docs/business-model/`; a `#confirmed` KB entry the code contradicts is escalated, not overwritten. *minor*

**What it says**

- Never invent a purpose. A purpose (why a rule exists, what a capability is for) is stated in the body only from a person's answer in `## Open questions`, the stories of the plan that built the feature (`docs/plans/**`, also `implemented/`; the ids go in the stamp's `stories`), or a `#confirmed` KB entry. Anything else is a row in `## Open questions`. Never write a tier tag or `#confirmed`. *blocker*
- An answered question is folded in before anything else is written: one plain sentence in the body where the rule is stated (and in *Rules and limits* when it changes a row), then the row is removed and its id never reused. An answer the code contradicts is not folded; the report escalates both readings. *major*
- Where the code and a story disagree, the guide states what the code does; the difference goes to the delivery note and the report, never into the guide as intended behaviour. *major*
- Nothing unreachable is written up as a capability. Code wired to a trigger outside the repository (a message nothing in the repo publishes, a caller in another service) is documented, with an open question "who starts this?". *major*
- Defects found while tracing go to the run's report, routed to `code-auditor` — never into the guide as intended behaviour. Behaviour is stated neutrally: bug, defect, flaw, broken, wrong, mistake, vulnerability and "should have" are lint warnings, quoted product text exempt. *major*
- A timing or delivery guarantee ("exactly once", "immediately", "as soon as", "in real time"…) is written only where the code shows it; a roadmap promise ("not yet", "coming soon") never. *major*

**Shape**

- Opens with `## In short`: three to five bullets, one sentence each, saying what people can do, the rules that matter most with their numbers, and what happens without anyone acting — no bold, no links, no formula, nothing the body does not say again. *major*
- Then `## Who uses it`, listing every role that acts on the feature — users, staff, **administrators** — in the order they meet it; `## How it fits together` (key ideas, and one Mermaid diagram of nine nodes at most); then one `## For <role>` section per role, in that order, with a `### <task>` per thing they do in lifecycle order. Optional: `## What happens automatically`, `## Rules and limits`, `## How it is calculated`, `## A <period> in numbers`, `## Good to know`, `## See also`; then `## Open questions` and `## About this document`. *major*
- The diagram is a `flowchart LR` of the people and what happens in order. It is a `stateDiagram-v2` only when the product itself shows the person a status, and then its states are those labels, spelled the same. Every node and arrow label is something the guide says. *major*
- Tasks come from what people do, never one per endpoint. Administration and settings screens are tasks under the administrators' section, written like any other person's — never only a row in *Rules and limits*. *major*
- A task has a `**Where:**` path, numbered steps that are the person's own actions (at most seven), and `**What happens next**` holding only what they then see, receive or are charged (at most five). A task with no screen carries no `**Where:**`, no bold label and no screenshot. *major*
- A task holds no formula: its outcome says the result in one sentence and points to `## How it is calculated`. The `**Example**` stays in the task, with its arithmetic lines after the marker. *major*
- Automatic work, each `###` under `## What happens automatically`, opens with `**When:**` (the moment or event, for whom) and lists `**What people notice**` in at most five bullets, each something a named person sees, receives, is charged or loses. No numbered system steps, no bookkeeping, no `**Trigger:**` or `**Result:**`, no screenshot. *major*
- `## Rules and limits` lists every business rule the guide states anywhere — a threshold, cut-off, limit, eligibility condition, effect of a change, configurable value — as a row of `| Rule | Value | Where you meet it | Can it be changed? |`, in the order a person meets them. *Where you meet it* names the task or automatic work in italics, or says "everywhere". Layered configuration adds a `Level` column after `Rule` and one precedence line above the table. Left out only when the trace found no rule, and the report says so. *major*
- `## How it is calculated` holds each formula under a `###` in the client's words: `Name = expression` on its own line, then `Where:`, plain-text math, with rounding and conventions stated; never code. Present whenever anything is calculated. *major*
- `## See also` is a plain list of at most six entries, `- [<Guide name>](<file>.md) — <why a person would go there>`, with nothing about which area owns, reads or writes what. *minor*
- `## Open questions` is `| # | Question | Why it matters | Answer |`, numbered `Q1…`, never renumbered; *Answer* stays empty until a person fills it. *major*
- Bold is only a screen label, exactly as the running screen shows it. Callouts are `[!NOTE]`, `[!TIP]`, `[!IMPORTANT]` and `[!WARNING]` (only for what cannot be undone or charges money), at most one per task. *major*
- Internal ids (`AREA-`, `FLOW-`, `ENT-`…) and story ids appear only in the stamp comment. Length: 2,500 words at most, outside fenced blocks, `## About this document` and the stamp. *major*

**Language**

- Uses the client's own terms from the trace's `Client vocabulary` table and the running screen; a refusal quotes the exact user-facing message. *major*
- Client language only: no class, method, table or column names, file names, status codes, exception types, framework nouns, jargon (endpoint, payload, handler, idempotent…), tier tags or `file:line`. A word that needs defining is replaced. A client's own technical-sounding word stays only when the product shows it. *major*
- The worked example sits in the task that computes, numeric whenever there is a calculation, threshold, layered setting or time-based process. Every number used as a rule is the code's exact value, the arithmetic is recomputed after any change, one cast runs throughout, and it never extends past what the code says. *major*

**Screenshots**

- Captured from a running **non-production** environment, signed in with a test login for the role the task belongs to — never from production, a mock-up, a design file or memory. Only a person can waive them, and the waiver is recorded in *About this document*. *blocker*
- Screenshots never block the text. With no environment, the guide is written in full with `**Where:**` paths and labels from the trace's `Client vocabulary`, holds no image and records `**Screenshots:** pending — <why>`; the report says what is needed. A later run given the environment signs in as each role, checks every bold label against the screen (the screen wins; a difference is fixed in the guide and raised as an open question), captures, and replaces the `pending` line, without a new trace. *major*
- At most one per task, only for a task with a `**Where:**` line, six per guide at most; never one per step. Chosen where the picture saves the most words: the first time a person meets a screen, a form with several fields, a busy administration screen. *major*
- Placed right under the task's `**Where:**` line as `![<what the screen shows, in the client's words>](screenshots/<NNN>-<slug>/<task-slug>.png)`; the alt text is never empty. *major*
- Shows the task's screen in the state the task describes, the example's values when the task has an example, and every label the steps name, spelled the same. Test data only: no real person's data, no secret, key, token or internal address. *blocker*
