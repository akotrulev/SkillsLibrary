# Store compliance — audit fragment (section L)

Rows `L1…` are permanent. A stack's conformance checklist section **L — Privacy & store compliance** holds no rows of its own: it takes the rows below whose `Stacks` column names its stack (`rn`, `ios`, `android`), and a finding `L5` is row L5 here. Append new rows at the end with the next number; never renumber.

**How to read a row.** *Check* = the invariant. *Violation looks like* = what disqualifies it. *Find it with* = a mechanical lead — a hit is never a finding until the code is read. *Sev* = default severity (blocker — a store rejection or block). A row marked **console only** is reported as `likely mismatch — verify in App Store Connect / Play Console`, **never as passed**. A row marked **requires dynamic test** cannot be proven from source and is reported unverified.

Recipes use `rg`. Globs: `rn` → `app.json`, `app.config.*`, `package.json`, `*.ts,*.tsx`; `ios` → `*.swift`, `Info.plist`, `*.xcprivacy`, `*.entitlements`; `android` → `*.kt,*.kts,*.xml`, `AndroidManifest.xml`.
