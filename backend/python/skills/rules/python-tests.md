# Python test standards (pytest)

Severity tags as in the core Python rules. The codebase wins where it consistently does otherwise.

- In process only: no `docker run`, no HTTP call to the worker, no network. A test that runs the image or asserts what the TypeScript side sees belongs to the container contract suite. *major*
- Names read `test_should_<outcome>_when_<condition>`; the Arrange / Act / Assert shape is the explanation, with no comments. *minor*
- Each assertion expects one value: `assert verdict.reason == "polyglot"`, never `in (…)` or `or`. *major*
- No `try`/`except` in a test body (use `pytest.raises(Type, match=…)`), no `if`/`for` driving assertions (use `parametrize` with readable `id=`s). *major*
- A collaborator is faked with a plain class implementing its `Protocol`. Never `mock.patch` the module under test; expose the seam instead. *major*
- Hostile fixtures are generated by builders in `tests/fixtures.py`, each with a test proving the fixture is hostile; a strip test on a JPEG that never carried GPS proves nothing. *major* No checked-in binary fixture. *minor*
- `tmp_path` only; no module-level image, no shared `BytesIO`, the environment changed only through `monkeypatch`; any test runs alone, in any order. *major*
- Model tests carry `@pytest.mark.model`, skip when `U2NET_HOME` is unset (and the skip is reported), and assert one geometric fact, never a pixel-exact mask. *major*
- Every `Rejected.reason` literal is some test's expected value. *minor*
- A failed validation asserts `errors()[0]["loc"]` and `["type"]`, never the message string. *minor*
- Do not test type aliases, `Literal` sets or the `Settings` field list; `hypothesis` strategies are bounded and never generate images. *minor*
- New code ships with tests covering at least 80% of the branches it wrote, measured with `pytest --cov-branch` as `covered_branches ÷ num_branches`, not `percent_covered`. Only an asserting test counts; exclusions are named, never `# pragma: no cover` on code with behaviour. *major*
